Linux-এ প্রতিটা ফাইলে তিন রকম অনুমতি থাকে:

- `r` (read): পড়া।
- `w` (write): বদলানো বা লেখা।
- `x` (execute): program হিসেবে চালানো। ফোল্ডারের বেলায় ভেতরে ঢোকা।

## ls -l পড়া

```
-rw-r--r-- 1 dev dev 195 Nov 15 10:20 notes.txt
```

প্রথম অক্ষর ধরন: `-` ফাইল, `d` ফোল্ডার। তারপর তিনটা তিনটা করে তিন দল:

| অংশ | কার জন্য | এখানে |
| --- | --- | --- |
| `rw-` | মালিক (`dev`) | পড়া আর লেখা |
| `r--` | group (`dev`) | শুধু পড়া |
| `r--` | বাকি সবাই | শুধু পড়া |

```terminal
$ ls -l
$ ls -l scripts
```

## script চালাতে x লাগে

`backup.sh`-এ `x` নেই, তাই চালাতে গেলে `Permission denied` আসে। `chmod +x` দিয়ে অনুমতি দিলে চলে।

```terminal
$ cd scripts
$ ./backup.sh   # x নেই, তাই চলবে না
$ chmod +x backup.sh
$ ls -l
$ ./backup.sh
```

`./` মানে "এখনকার ফোল্ডারের এই ফাইল"। শুধু `backup.sh` লিখলে shell সেটা `PATH`-এর ফোল্ডারগুলোতে খোঁজে, এখানে না।

## সংখ্যা দিয়ে chmod

`r` = 4, `w` = 2, `x` = 1। প্রতি দলের জন্য যোগ করে একটা অঙ্ক:

- `chmod 644 ফাইল`: মালিক পড়া-লেখা (6), বাকিরা শুধু পড়া (4)। সাধারণ ফাইলের জন্য।
- `chmod 755 ফাইল`: মালিক সব (7), বাকিরা পড়া-চালানো (5)। script আর ফোল্ডারের জন্য।
- `chmod 600 ফাইল`: শুধু মালিক পড়া-লেখা। গোপন ফাইলের জন্য, যেমন `.env`।

```terminal
$ chmod 600 notes.txt
$ ls -l notes.txt
```

`chmod 777` সবাইকে সব অনুমতি দেয়। এটা চলে, কিন্তু server-এ বড় নিরাপত্তার ঝুঁকি। এই simulator সেটা নিয়ে সতর্ক করে।
